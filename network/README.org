
** About
Neural network simulator developed by Felix Hoffmann for his PhD.
Original at https://github.com/synsrv/src_net.

Network simulation using Brian 2 and Pypet written to analyse the survivability of transient synapses of cortical neurons.

** Requirements
To run the network simulation a Python 3.12 environment with Brian 2 and Pypet is required.
The pinned dependencies are listed in ~environment.yml~; the upstream Brian2 release from PyPI is
used, no patched Brian2 version is needed anymore.

In addition, the following has to be installed on the system:
- Git
- a C++ compiler (~g++~), used by Brian2's ~cpp_standalone~ device
- LaTeX with the ~tgheros~, ~sansmath~ and ~siunitx~ packages, used for the figures

Below is an example installation routine for setting up a conda environment.
This assumes that you already have anaconda or miniconda installed.

#+BEGIN_SRC sh
#!/bin/sh

conda env create -f environment.yml
conda activate synlife

#+END_SRC

** Installation

It is highly recommended to limit the level of parallelization when building the standalone_cpp simulator.
In ~$HOME/.brian/user_preferences~ write, where ~4~ is the number of CPU cores your PC has:
#+BEGIN_SRC ini
[devices.cpp_standalone]
extra_make_args_unix = ["-j4"]
#+END_SRC

** Run a simulation
To verify your installation, within ~src_net~ run

#+BEGIN_SRC sh
./run_test.sh -l tests/net_tests/test_standard_net/
#+END_SRC

This will create a directory ~tests/~ on the same level as ~src_net~ where the code is copied an executed.

** Explore parameters

To run simulations exploring different parameter sets, create an ~explored_params.py~ in ~src_net/net/~, as for example found in any of the tests in ~net_tests/~. In the ~input_dict~ of ~explored_params.py~ specify the parameter setting of your choice and the runn simulation via

#+BEGIN_SRC 
./run.sh -l -n 2 -P "_two-concurrent-sims" -E
#+END_SRC

This will create ~running/~ and ~completed/~ directories on the same level as ~src_net/~. Once finished, the simulation directory is moved from ~running/~ to ~completed/~.

Runs started with ~-E~ record the git commit and refuse to start if there are uncommitted changes, so commit your ~explored_params.py~ first.

** Run on a Slurm cluster

There are two ways:

1. Interactively from a login node: without ~-l~, ~run.sh~ and ~run_test.sh~ start the simulation
   with ~srun~ (partition ~x-men~, or ~sleuths~ with ~-s~; change ~CLUSTER~ in ~run.sh~ for other
   clusters). Give the memory with a unit, e.g. ~./run.sh -n 2 -c 2 -m 8G -P _myrun -E~.
2. As a batch job with ~sbatch submit.slurm~ (from the repository root). The job runs
   ~run_test.sh~ or ~run.sh~ with ~-l -d~, i.e. inside the job and in the foreground; see the
   comments in ~submit.slurm~ for how to run your own parameters and what to request.

Without conda, create the environment as a venv on a login node (needs Python 3.12 and
internet access): ~PYTHON=python3.12 network/setup_env.sh~, then ~source network/myenv/bin/activate~.
The packages are pinned in ~requirements.txt~ (same versions as ~environment.yml~).
Also limit the parallel compilation (~~/.brian/user_preferences~, see Installation) to the number
of cores you request.

** Run tests

There are multiple sets of tests currently, they fall in three broad categories:
1. tests that can be run with ~pytest~: ~pytest tests/pytests~
2. unit tests of the analysis methods, run from within ~analysis/~: ~PYTHONPATH=. pytest test~
3. all other tests, which can be run using ~./run_test.sh~ as shown above
