
** About
Neural network simulator developed by Felix Hoffmann for his PhD.
Original at https://github.com/synsrv/src_net.

Network simulation using Brian 2 and Pypet written to analyse the survivability of transient
synapses of cortical neurons.

** Installation

Needed on the computer (or the cluster nodes):
- conda, e.g. Miniforge (can be installed without admin rights, see below)
- a C++ compiler (~g++~), used to compile the simulation
- LaTeX with the ~tgheros~, ~sansmath~ and ~siunitx~ packages, used for the figures
- git

Create the Python environment ~synlife~ (Python 3.12, Brian2, pypet, ...; the versions are pinned
in ~environment.yml~), from the repository root:

#+BEGIN_SRC sh
conda env create -f network/environment.yml
conda activate synlife
#+END_SRC

If conda is not available (e.g. on a cluster), install Miniforge in your home directory first:

#+BEGIN_SRC sh
curl -L -O https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
bash Miniforge3-Linux-x86_64.sh -b -p $HOME/miniforge3
source $HOME/miniforge3/bin/activate
#+END_SRC

To check the installation, run the standard test (within ~network/~, takes ~2 minutes):

#+BEGIN_SRC sh
./run_test.sh tests/net_tests/test_standard_net
#+END_SRC

** Running simulations

1. Set the parameters in ~network/net/explored_params.py~ (defaults and their documentation in
   ~net/standard_params.py~). Each entry is a list of values: lists of length n give n
   simulations (simulation k uses the k-th value of each list), lists of length 1 are used for
   all of them. For example, ~'random_seed': [7910, 13278, 37459]~ gives 3 simulations. The
   variable ~name~ at the end of the file names the run.
2. Run, within ~network/~ (with the environment activated):

   #+BEGIN_SRC sh
   ./run.sh
   #+END_SRC

   All simulations run in parallel (at most one per core). Options: ~-n N~ runs at most N at a
   time (each needs ~4 GB of memory with N_e=1600), ~-b~ runs in the background.
3. The run is done in ~running/<timestamp>_<name>/~ (at the repository root) and moved to
   ~completed/<timestamp>_<name>/~ when it has finished. If a simulation fails, the run stays in
   ~running/~ with its error in ~failed_run_<k>.txt~.

A run folder contains (simulation k = 0000, 0001, ...):

| ~run.log~                  | the complete output                                               |
| ~figures/<figure>/<k>.png~ | figures of each simulation                                        |
| ~builds/<k>/raw/~          | raw data of each simulation (spikes, turnover, weights, parameters) |
| ~data/<name>.hdf5~         | pypet trajectory with all parameters and the connectivity         |
| ~src/~                     | the code that was run                                             |
| ~git_commit.txt~           | the git commit of the code                                        |
| ~uncommitted_changes.diff~ | changes of the code not committed to git (if any)                 |

A full simulation with the default parameters (N_e=1600, T2=5000 s, T5=1500 s) takes about
3-3.5 h.

** Running on a Slurm cluster

The job script ~submit.slurm~ (repository root) runs ~run.sh~ on one whole node, so that all
simulations run in parallel. It expects the repository in ~~/projects/SynapticLifetimes~ (line
~REPO=...~ in ~submit.slurm~). Submit from the folder where the job logs should go, e.g.
~~/submitted~:

#+BEGIN_SRC sh
cd ~/submitted
sbatch ~/projects/SynapticLifetimes/submit.slurm
#+END_SRC

- ~squeue -u $USER~ shows the job, ~tail -f synlife_<jobid>.log~ its progress and errors.
- The results are saved in ~completed/<timestamp>_<name>/~ as for local runs.
- Options of ~run.sh~ can be added: ~sbatch ~/projects/SynapticLifetimes/submit.slurm -n 4~.
- At the top of ~submit.slurm~: the partition (~general1,general2~ on Goethe) and the time
  limit (12 h). It activates the conda environment of ~$HOME/miniforge3~; change that line if
  conda is installed elsewhere, and add ~module load~ lines if the cluster needs them for ~g++~
  or LaTeX.

** Analysing results

The figures are made at the end of each simulation. Further analysis scripts in ~analysis/~ can be
run on a finished run with its own code, e.g.:

#+BEGIN_SRC sh
cd completed/<run>
PYTHONPATH=src python -m analysis.t5_peaks
#+END_SRC

Weight snapshots (~builds/<k>/raw/synee_a.p~, ...) are read with ~analysis.utils.WeightSnapshots~.
To run the post-processing (survival and turnover statistics, their figures) of a finished run
again, e.g. after changing the analysis code: ~./src/post_process.sh~ inside the run folder.

** Tests

Within ~network/~:
1. network tests (a short simulation and checks of its results):
   ~./run_test.sh tests/net_tests/<test>~ (run folder in ~tests/testing/~)
2. tests with ~pytest~: ~pytest tests/pytests~
3. unit tests of the analysis, from within ~analysis/~: ~PYTHONPATH=. pytest test~
